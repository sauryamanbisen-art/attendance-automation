# Gmail OAuth 2.0 Setup & Controlled Live Delivery Runbook

This guide describes the complete procedure for configuring Google Cloud OAuth 2.0, authorizing the Gmail Notification Provider in the local web application, verifying tokens securely, and performing one controlled live email test.

---

## 1. Safety & Architecture Invariants

1. **Fail-Closed by Default:** Real email transmission is strictly prohibited unless `DRY_RUN=false` is explicitly set and the provider is authorized with valid credentials.
2. **Minimal OAuth Scopes:** Only the least-privileged scope for message sending is requested:
   - `https://www.googleapis.com/auth/gmail.send`
   - This scope allows sending messages only. It cannot read inboxes, delete emails, or access contacts.
3. **No Passwords or Secrets in Code:** Never use Gmail passwords or App Passwords. Authentication uses OAuth 2.0 authorization codes and access tokens.
4. **Token Security:** Stored refresh tokens are persisted in `credentials/gmail_token.json` with POSIX `0600` permissions (`stat.S_IRUSR | stat.S_IWUSR`). The `credentials/` folder is git-ignored.
5. **CSRF Protection:** State parameters generated by [`OAuthStateManager`](file:///Users/sauryamanbisen/attendance-automation/app/notifications/oauth.py#L273-L300) are cryptographically random, single-use, and valid for 10 minutes.

## 2. Google Cloud Console Configuration

Follow these steps in the [Google Cloud Console](https://console.cloud.google.com/):

### Step 2.1: Enable the Gmail API
1. Select or create your Google Cloud project (e.g. `attendance-automation-local`).
2. Navigate to **APIs & Services > Library**.
3. Search for **Gmail API** and click **Enable**.

### Step 2.2: Configure the OAuth Consent Screen
1. Navigate to **APIs & Services > OAuth consent screen**.
2. Select **External** (or **Internal** if using a Google Workspace domain) and click **Create**.
3. Fill in:
   - **App name:** `Attendance Automation`
   - **User support email:** Your email address
   - **Developer contact information:** Your email address
4. Under **Scopes**, click **Add or Remove Scopes**, filter for `gmail.send`, select `https://www.googleapis.com/auth/gmail.send`, and click **Update**.
5. Under **Test users**, add your own Gmail address (the account that will send the emails).
6. Click **Save and Continue**.

### Step 2.3: Create OAuth Client ID
1. Navigate to **APIs & Services > Credentials**.
2. Click **Create Credentials > OAuth client ID**.
3. Select **Application type:** `Web application`.
4. Name: `Attendance Automation Local Client`.
5. Under **Authorized redirect URIs**, add both:
   - `http://localhost:8000/api/auth/gmail/callback`
   - `http://127.0.0.1:8000/api/auth/gmail/callback`
6. Click **Create**.
7. Copy the generated **Client ID** and **Client Secret**.

## 3. Local Application Configuration

1. In your local repository, copy `.env.example` to `.env` if you have not already:
   ```bash
   cp .env.example .env
   ```
2. Configure the following variables in `.env`:
   ```dotenv
   # Keep dry run true initially
   DRY_RUN=true
   EMAIL_PROVIDER=gmail
   NOTIFICATION_SENDER_EMAIL=your-actual-email@gmail.com

   # Paste credentials from Google Cloud Console
   GMAIL_CLIENT_ID=your-client-id.apps.googleusercontent.com
   GMAIL_CLIENT_SECRET=your-client-secret
   GMAIL_REDIRECT_URI=http://localhost:8000/api/auth/gmail/callback
   GMAIL_TOKEN_FILE=credentials/gmail_token.json
   ```
   > [!IMPORTANT]
   > Do not commit `.env` to git. It is already included in `.gitignore`.

## 4. Connecting via the Web Dashboard

1. Start the local server:
   ```bash
   .venv/bin/uvicorn main:app --host 127.0.0.1 --port 8000 --reload
   ```
2. Open your browser and navigate to the dashboard settings:
   ```
   http://127.0.0.1:8000/dashboard#settings
   ```
3. Look at the **Notification Providers** card:
   - If `GMAIL_CLIENT_ID` is present, Gmail will display the **Disconnected** badge with a **Connect** button.
4. Click **Connect**:
   - You will be redirected to Google's consent screen.
   - Select your test user account and click **Continue** (accepting unverified developer app warnings for local apps).
   - Upon granting consent, Google redirects to `/api/auth/gmail/callback`, which exchanges the authorization code for tokens, saves `credentials/gmail_token.json`, and returns a `307 Redirect` to `/#settings?oauth_success=gmail`.
5. The Settings page will now show the green **Connected** badge with your email address.

## 6. Performing Controlled Tests

### Step 6.1: Dry-Run Simulation (Safe)
Test payload generation and provider formatting without contacting Google APIs:

```bash
.venv/bin/python scripts/verify_gmail_provider.py --dry-run
```

Verify that the output displays:
```text
Dry-run Outcome : success=True, is_dry_run=True
Message Preview :
PROVIDER: gmail
TO: test-recipient@example.edu
SUBJECT: [VERIFICATION] Attendance Discrepancy Notice
...
```

### Step 6.2: Controlled Single Real Delivery Test
When ready to test live sending to **your own mailbox**:

1. Run the verification script with your own email address as recipient:
   ```bash
   .venv/bin/python scripts/verify_gmail_provider.py --send-test-email your-actual-email@gmail.com
   ```
2. The script displays a safety warning:
   ```text
   !!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
    CAUTION: REAL EMAIL TRANSMISSION REQUESTED
   !!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
    Recipient : your-actual-email@gmail.com
    Sender    : your-actual-email@gmail.com
   !!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
   Type 'CONFIRM' to send real test email:
   ```
3. Type `CONFIRM` and press Enter.
4. Output upon success:
   ```text
   Sending real email via Gmail API...
   Send Success! Message ID: 191a2bc345def678
   ```
5. Check your inbox for the test message.

## 7. Revoking / Disconnecting

To revoke local credentials at any time:
- In the Web Dashboard: Navigate to **Settings** and click the **Disconnect** button next to Gmail.
- Or delete the token file:
  ```bash
  rm -f credentials/gmail_token.json
  ```
- To revoke authorization remotely, visit [Google Account Permissions](https://myaccount.google.com/permissions) and remove access for `Attendance Automation`.
